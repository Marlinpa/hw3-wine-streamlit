# Подбор вин по качеству — ДЗ 3

Приложение использует сохранённый пайплайн `StandardScaler + LogisticRegression`. Вероятность класса 1 означает экспертную оценку вина не ниже 7 из 10. Внутри приложения модель не обучается.

## Запуск

Версия интерпретатора: **Python 3.13.5**. Версии библиотек указаны в `requirements.txt`.

Из папки `wine_app/`:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте адрес из вывода Streamlit, обычно `http://localhost:8501`. Все файлы модели уже подготовлены.

Для повторного запуска ноутбука на другом компьютере распакуйте `wine_app.zip` рядом с ним: последняя ячейка использует исходные файлы приложения для сборки архива.

Для повторного обучения выполните весь `HW3_MMDA_solved.ipynb` из родительской папки либо запустите там `python prepare_app_files.py`. Оба способа используют исходный CSV задания и одинаковое разбиение с `random_state=42`: 70% train и 30% test. Порог выбирается на валидационной части train; затем модель переобучается на всём train. Условие recall >= 0.7 относится к валидации и не гарантируется для новых данных.

## Возможности

- «Одно вино»: 11 числовых признаков и переключатель красного/белого вина. Диапазоны и медианы взяты из `test.csv` по условию задания.
- «Модельные метрики»: precision, recall, F1, матрица ошибок, ROC и PR с точками текущего порога.
- «Пакетный прогноз»: загрузка CSV, проверка признаков, скачивание результатов и образца входного файла.
- «Коэффициенты модели»: веса стандартизированных признаков и признаки с наибольшим положительным/отрицательным влиянием.

CSV должен содержать `fixed_acidity`, `volatile_acidity`, `citric_acid`, `residual_sugar`, `chlorides`, `free_sulfur_dioxide`, `total_sulfur_dioxide`, `density`, `pH`, `sulphates`, `alcohol`, `is_red`. Столбец `target` не требуется. Значения должны быть числовыми и конечными, `is_red` равен 0 или 1. Результат добавляет `probability_good` и `recommend`.

## Кэширование

`st.cache_resource` хранит один объект модели между перезапусками скрипта. `st.cache_data` кэширует тестовую таблицу и рассчитанные вероятности. При изменении порога вероятности берутся из кэша, пересчитываются только метки и метрики. Без декоратора `joblib.load` заново читал бы модель с диска при каждом действии пользователя. После замены модели перезапустите сервер для сброса кэша.
